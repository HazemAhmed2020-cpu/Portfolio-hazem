# تعديل نسخة Vercel ببرنامج DB Browser for SQLite

## ما الذي تغيّر؟

نسخة Vercel الآن **موقع عرض عام ثابت**. وقت البناء، يُقرأ ملف SQLite مخصص للمحتوى، وتُصدّر منه بيانات عامة إلى ملفات JSON يقدّمها Vercel مع الصور والواجهة. لا يوجد سيرفر Node.js دائم أو ملف SQLite قابل للكتابة داخل دوال Vercel.

**هذه النسخة لا تحتوي على Studio أونلاين أو رفع ملفات من المتصفح أو Inbox لحفظ رسائل الزوّار.** يمكن للزائر إرسال رسالة من الفورم داخل الصفحة عبر FormSubmit، مع بقاء البريد والهاتف كوسيلتي تواصل بديلتين. هذا هو مسار النشر الذي وافقت عليه، وليس بديلًا يدّعي تشغيل الإدارة أو حفظ الرسائل.

النسخة الكاملة Express/SQLite ما زالت موجودة في الكود، ويمكن تشغيلها على استضافة Node.js بقرص دائم.

## الملف الذي تفتحه

```text
content/portfolio-public.sqlite
```

هذا ملف جديد يحتوي على **المحتوى العام فقط**. ليس هو قاعدة البيانات الخاصة بالتطبيق.

**لا ترفع `data/portfolio.sqlite` أو مجلد `private/` إلى GitHub.** قاعدة التشغيل القديمة قد تحتوي على بيانات إدارة وجلسات ورسائل. لا تضع كلمات مرور أو مفاتيح API أو بيانات خاصة داخل ملف المحتوى العام.

## خطوات التعديل والنشر

1. نزّل أحدث نسخة من المستودع، أو اسحب أحدث التغييرات باستخدام Git.
2. افتح [DB Browser for SQLite](https://sqlitebrowser.org/)، ثم اختر **Open Database** وحدد `content/portfolio-public.sqlite`.
3. افتح **Browse Data** واختر الجدول المناسب من القائمة.
4. عدّل الخلايا المطلوبة.
5. اضغط **Write Changes**، ثم **Close Database** قبل الرفع، لضمان حفظ التعديلات في ملف قاعدة البيانات نفسه.
6. ارفع الملف المعدّل إلى نفس المسار في GitHub واعمل Commit. لا ترفع ملفات `-wal` أو `-shm` أو قاعدة التشغيل الخاصة.
7. Vercel سيعيد النشر تلقائيًا إذا كان المشروع متصلًا بالمستودع. انتظر نجاح الـDeployment ثم حدّث الصفحة.

## الجداول

| الجدول | محتواه |
|---|---|
| `profile` | الاسم، الوظيفة، البريد، الهاتف، الروابط، الصورة، المقدمة، ونص About. اترك `id` بالقيمة 1. |
| `projects` | عناوين المشاريع ووصفها وروابطها وصورها وحالة العرض. |
| `project_technologies` | تقنيات كل مشروع؛ `project_id` يجب أن يطابق مشروعًا موجودًا. |
| `project_highlights` | نقاط شرح المشروع؛ `project_id` يجب أن يطابق مشروعًا موجودًا. |
| `credentials` | التدريبات، الجهة المانحة، التاريخ، وصف التدريب، وروابط مستنداته. |
| `skills` | المهارات. قيمة `section` واحدة من `frontend` أو `backend` أو `tools`. |
| `education` | الجامعات والدرجات والتواريخ والملاحظات. |
| `achievements` | نقاط الإنجازات. |

### قيم مهمة

- `sort_order`: رقم ترتيب العنصر؛ الأصغر يظهر أولًا.
- `published`: القيمة `1` تعرض العنصر، و`0` تخفيه من الواجهة.
- `featured`: القيمة `1` تجعل المشروع مميزًا.
- `show_source`: القيمة `0` تخفي زر المصدر. تظل هذه القيمة صفرًا في CONFIT حسب طلبك.
- `available`: `1` لإظهار حالة الاستعداد للفرص، أو `0` لإخفائها.
- `demo_mode`: إحدى القيم `live` أو `login` أو `demo` أو `preview` أو `paused`.
- `short_issuer`: مثل `ITI` أو `NTI` أو `MCIT` أو `AM` لعرض الشعارات الموجودة.

**كل ما داخل هذا الملف يمكن قراءته من المستودع العام، حتى الصفوف التي تحمل `published=0` أو روابط أزرار مخفية.** الإخفاء هنا يخص واجهة العرض وليس سرية البيانات. لا تستخدمه لحفظ مسودات أو معلومات خاصة.

## الصور والسيرة الذاتية

لإضافة صورة، ضعها في `public/images/` داخل المستودع، ثم استخدم مثلًا:

```text
/images/my-project.png
```

وللسيرة الذاتية أو ملف PDF، استخدم `public/resume/` ورابطًا مثل:

```text
/resume/my-cv.pdf
```

لا تستخدم روابط `/media/` الخاصة برفع الملفات في نسخة السيرفر؛ تلك الملفات لا تُنشأ في نسخة Vercel الثابتة.

## أوامر المعاينة

```bash
npm ci
npm run build:static
npm run preview:static
```

لا تعِد تشغيل `npm run content:init` فوق ملف عدّلته. الأمر يرفض الاستبدال عمدًا لحماية تعديلاتك.

لتشغيل النسخة الأصلية ذات Studio وInbox محليًا:

```bash
npm start
```

تشغيل النسخة الأصلية لا ينشر تعديلات قاعدة تشغيلها الخاصة تلقائيًا في ملف المحتوى العام. مسار Vercel يعتمد على ملف `content/portfolio-public.sqlite` الموجود في GitHub.

## التحقق من النشر

- `/deployment-health.json` يبيّن أن النشر في وضع `static` مع تعطيل Studio وInbox.
- `/api/portfolio` رابط قراءة فقط لنسخة المحتوى العام، وليس قاعدة بيانات قابلة للكتابة.
- `/api/health` يعرض حالة النسخة الثابتة بوضوح.
- `/admin` يعرض شرح طريقة التعديل المحلية، ولا يقدّم نموذج دخول وهميًا.
- زر Send message يرسل طلبًا عبر AJAX إلى FormSubmit من داخل الصفحة. رابط البريد النصي البديل فقط يفتح تطبيق البريد. نجاح الطلب يعني قبول خدمة الإرسال، وليس ضمان موضع الرسالة داخل Inbox بدل Spam. الرسائل لا تُحفظ في ملف SQLite العام.

## نموذج التواصل

تعديل المحتوى عبر DB Browser لا يرسل البريد بنفسه. الفورم موصول بخدمة FormSubmit مستقلة عن قاعدة المحتوى. عنوان الاستقبال هو `email` في جدول `profile`. إذا غيّرته، فعّل العنوان الجديد لدى FormSubmit. لا تضع كلمة مرور Gmail أو أي مفتاح خاص في ملف المحتوى. راجع `CONTACT_FORM_AR.md` للتفعيل وحدود التسليم والخصوصية.
